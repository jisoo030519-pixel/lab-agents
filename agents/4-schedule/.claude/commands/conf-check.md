학회 마감 감시 1회 실행. 아래 절차를 순서대로 따른다.

## 1. 대상 확인

```
python watch.py list
```

출력된 학회만 확인한다. `targets.yaml`에 없는 학회는 임의로 추가하지 않는다.

## 2. 수집

각 학회마다 `url`을 열어 확인한다. 학회 수가 여럿이면 병렬로 진행한다.

- 먼저 WebFetch로 시도한다. JS 렌더링이 필요하거나 내용이 비면 브라우저 도구로 전환한다.
- 홈페이지만 있고 일정이 안 보이면 "학술대회", "행사", "공지사항", "Call for Papers"
  메뉴를 한 단계 따라 들어간다. 그래도 없으면 WebSearch로 보완한다.
- 그 학회의 `watch` 목록에 있는 종류만 수집한다.
- 프로그램북·안내문 PDF 링크를 발견하면 URL을 기억해 두고 보고에 포함한다
  (발표 일정 추출은 `/conf-program` 이 담당한다).

**추출 규칙**

- `due`는 반드시 `YYYY-MM-DD` 형식. 연도가 안 적혀 있으면 오늘 날짜 기준으로 추론하되
  추론했다는 사실을 `note`에 남긴다.
- "9월 중순", "추후 공지"처럼 확정 날짜가 아니면 `due`를 `null`로 두고 원문을 `note`에 적는다.
  **날짜를 지어내지 않는다.** 이 에이전트에서 가장 위험한 실패는 없는 마감일을 만들어내는 것이다.
- 마감이 연장된 정황("연장", "extended")이 보이면 `note`에 명시한다.
- 페이지 접속 실패·구조 변경으로 못 읽은 학회는 그 학회를 통째로 건너뛰고,
  **결과 보고에 "확인 실패"로 반드시 명시한다.** 조용히 누락시키지 않는다.
  URL이 죽어 있으면 올바른 주소를 찾아 `targets.yaml` 수정을 제안한다.

## 3. 병합

수집 결과를 스크래치패드에 `found.json`으로 쓴다.

```json
[
  {"society":"한국화학공학회","event":"2026 가을 학술대회","kind":"abstract",
   "due":"2026-09-25","url":"https://...","note":""}
]
```

`kind`는 `abstract` / `full_paper` / `earlybird` / `registration` / `camera_ready` / `event` 중 하나.

```
python watch.py upsert-deadlines <found.json 경로>
python watch.py report
python watch.py ics
python watch.py sync
```

## 4. 보고

1. **신규·변경 건을 맨 위에** — 특히 마감일이 앞당겨졌거나 새로 뜬 초록 마감
2. 7일 이내 마감이 있으면 눈에 띄게
3. 확인 실패한 학회와 그 이유
4. `LATEST.md`를 SendUserFile로 첨부

변경이 하나도 없으면 "변경 없음 + 다음 마감 1건"만 짧게 보고한다. 리포트 전문을 다시 붙여넣지 않는다.

## 5. 대시보드 갱신

신규·변경 건이 있었다면 `python watch.py sync` 로 데이터를 주입하고,
같은 파일 경로로 Artifact를 다시 퍼블리시한다
(같은 URL이 유지되므로 랩 사람들이 쓰던 링크가 바뀌지 않는다).
